# 验收清单 — 官网赛事模块动态化 Demo

> 负责人：D。依据：分工细则 §13「最终验收清单」。
> 规则：**勾选 = 已按下述方法实际验证通过**；未勾选一律不算完成。截图可辅助，不替代真实运行。
> 演示全程使用虚构报名数据；Demo 完成不代表满足正式开放报名的部署、备份与安全要求。

## 验收环境与基线

- 本机基线：Node v24.18.0 / npm 11.16.0；`npm run build` 通过（tsc + vite，2026-11-10 记录）。
- 每次验收前确认当前分支已包含全部待验收提交，且从集成分支 `develop` 拉取最新代码。
- 跨电脑验收按 [`docs/runbook.md`](runbook.md) 执行（已交付：双平台命令、环境配置、备份恢复与常见问题）。

## 一、页面与导航

- [ ] 1. 原首页、动态和关于页面正常，赛事导航在手机和电脑可用。（A）
  方法：`npm run dev` 后逐页访问 `/`、`/#feed`、`/posts`、`/posts/:slug`、`/about`；浏览器切 ≤375px 宽度复核手机菜单。
- [ ] 2. 未登录访问管理页 / 管理接口被拒绝，回到登录页。（C 后台校验 + D 页面处理）
  方法：未登录直接打开 `/#/admin/competitions` 与 `GET /api/admin/competitions`，均应 401 / 跳转登录，不得出现数据。

## 二、比赛管理

- [ ] 3. 管理员能登录、新建草稿；草稿不在公开接口和页面出现。（D + C）
  方法：登录 → 新建比赛保存草稿 → 未登录窗口打开首页与赛事列表确认草稿不可见；`GET /api/competitions` 响应中无该草稿。
- [ ] 4. 发布后首页赛事预览、赛事列表和详情可见。（A + B）
  方法：后台发布 → 前台刷新首页（≤3 场）、列表、详情，三处均出现且信息一致。
- [ ] 5. 后台修改标题或截止时间后，前台刷新出现变化，无需改源码和重新构建。（A + B + D）
  方法：编辑保存 → 前台刷新核对；全程不重启 dev server、不重新 build。
- [ ] 6. 下架后公开不可见，也不能通过直接请求继续报名。（C）
  方法：下架 → 公开列表 / 详情消失；用旧 `id` 直接 `POST /api/competitions/:id/registrations` 应被拒绝。
- [ ] 7. 失败的操作不能显示成功（网络失败、后台报错有提示）。（A + B + D）
  方法：停掉后台服务后执行发布 / 报名，页面须出现明确错误提示，不得出现成功反馈。

## 三、报名流程

- [ ] 8. 用户报名后得到真实报名编号，管理员可查到同一条记录。（B + C + D）
  方法：前台提交报名 → 记录返回编号 → 管理端报名页按比赛查到同一条（姓名、邮箱、时间一致）。
- [ ] 9. 重复邮箱报名被后台拒绝，数据库没有重复记录。（C）
  方法：同比赛同邮箱提交两次，第二次应 409；检查数据库该比赛 + 规范化邮箱仅一条。
- [ ] 10. 截止报名被后台拒绝，不能仅依靠禁用前端按钮。（C + B）
  方法：把某比赛截止时间改为已过期 → 直接请求报名接口应被拒（400/409，按 api.md 错误码）；前端禁用仅作辅助。
- [ ] 11. 报名处理状态修改后，刷新管理页仍保留。（D + C）
  方法：待处理 → 已确认 → 刷新页面仍为已确认；对已确认记录重复确认应被后台拒绝或幂等（以 api.md 为准）。
- [ ] 12. 退出登录后直接请求管理接口被拒绝；公开接口没有报名个人信息。（C）
  方法：退出 → 带 Cookie 请求 `GET /api/admin/competitions` 应 401；检查公开接口响应不含报名人字段。

## 四、持久化与交付

- [ ] 13. 重启后台后比赛、报名和处理状态仍存在。（C）
  方法：完整流程产生数据后重启 server，重新核对管理列表与报名页数据完好。
- [ ] 14. 另一台电脑按说明可以安装、初始化和启动。（D）
  方法：找一台未开发过的电脑，仅凭 `docs/runbook.md` 从零安装到完整跑通；过程中记录每处含糊点并回填文档。
- [ ] 15. 前端构建与约定检查通过；无新增阻断问题。（B + D）
  方法：`npm run lint`、`npm run build` 通过；对比本文件「验收环境与基线」记录，区分基线已有问题与新增问题。
- [ ] 16. 完整流程连续演示两遍，使用虚构报名数据。（全员，D 组织）
  方法：登录 → 新建 → 发布 → 前台可见 → 报名 → 管理处理 → 重启数据仍在，连续两遍无阻断。

## 已知限制（持续更新）

- 骨架阶段（本周二）：管理端页面使用统一模拟数据，提交类操作均显示「未接入」，不伪造成功。
- 本周不包含：普通用户注册、复杂组队、作品上传、自动评测、排行榜、通知、富文本编辑、批量导出（细则 §1）。

## 演示步骤（D7 文档定稿后回填）

1. 启动：见 `docs/runbook.md`。
2. 演示脚本：登录 → 新建草稿 → 发布 → 前台核对 → 用户报名 → 后台处理状态 → 重启验证持久化。
3. 演示数据：使用本文件与 runbook 约定的虚构账号与虚构报名信息。
