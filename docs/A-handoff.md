# A 模块交接与验收

## 当前实现

- 电脑及手机导航新增赛事中心，详情页保持栏目高亮。
- 首页动态区之后、加入我们之前新增赛事预览，不改变原区块相对顺序。
- 首页请求真实接口，最多显示 3 场赛事；支持加载、空列表、错误重试、10 秒超时和卸载取消请求。
- 截止时间按北京时间展示；不根据客户端时间承诺一定可报名，由 B、C 在报名时校验。
- 接入约定路由；B、D 未交付页面之前显示明确占位，不模拟报名成功或管理员登录。

## 给 B、C 的接入约定

请求 `GET /api/competitions`，返回：

```json
{
  "data": [
    {
      "id": 1,
      "title": "接口示例比赛（非正式赛事）",
      "summary": "示例摘要",
      "registrationDeadline": "2026-11-20T18:00:00+08:00",
      "status": "published"
    }
  ]
}
```

这是待共同确认的接口格式，不代表 C 已实现。空列表必须返回 `{"data":[]}`；请求失败、格式错误与暂无赛事区分显示。后台只返回已发布数据并确定排序，A 保留顺序取前 3 条。首页每次挂载或重试都会重新请求，后台更新后刷新页面即可读取。

临时请求适配层在 `src/lib/competition-preview.ts`，不占用 B 的 `src/lib/api.ts`。B 交付统一请求工具后，在适配层替换请求实现；格式不一致也优先只改适配层。

B 负责配置 Vite 的 `/api` 转发到 C 的本地后台（原前端端口 3000，建议后台 3001），部署时配置同源 `/api` 反向代理。A 本次不修改公共开发配置；未配置转发或无后台时首页会显示可重试错误，不显示虚构赛事。

## 路由接入

`src/App.tsx` 中明确标注 B、D 占位 element。页面交付后由 A 添加真实 import 并替换 element：

| 路由 | 交付人 |
| --- | --- |
| `/competitions` | B |
| `/competitions/:id` | B |
| `/admin/login` | D |
| `/admin/competitions` | D |
| `/admin/competitions/new` | D |
| `/admin/competitions/:id/edit` | D |
| `/admin/competitions/:id/registrations` | D |

`/admin` 暂跳转 `/admin/login`。当前占位没有认证功能；接入 D 页面后需提供前端登录失效处理，C 必须保护管理接口。不能把路由占位当作管理系统完成。

## 本地启动

安装 Node.js 22.12 或更高兼容版本，在仓库根目录执行：

```sh
npm ci
npm run dev
```

浏览器以终端提供地址为准（原配置为 `http://localhost:3000/`）。构建检查：`npm run lint`、`npm run build`。

## A 验收清单

- [ ] 桌面导航进入 `#/competitions`，赛事详情页导航保持高亮。
- [ ] 390px 手机宽度下菜单能展开、进入赛事中心后关闭；平板导航不挤压。

- [ ] 500、非 JSON、字段错误显示错误提示；修复接口后点击重试恢复。
- [ ] 成功返回 4 条已发布比赛，只显示前 3 条，标题、摘要和北京时间正确。
- [ ] 每条赛事链接进入对应详情路由，全部赛事链接正常。
- [ ] 后台修改并发布后刷新首页，内容更新（待 C 交付后实测）。
- [ ] 原首页、动态、文章详情、关于、加入我们锚点正常。
