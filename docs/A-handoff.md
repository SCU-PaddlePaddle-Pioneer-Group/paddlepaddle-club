## 给 B、C 的接入约定

请求 `GET /api/competitions`，返回：

```json
{
  "items": [
    {
      "id": "11111111-1111-4111-8111-111111111111",
      "title": "接口示例比赛（非正式赛事）",
      "summary": "示例摘要",
      "registrationDeadline": "2026-11-20T18:00:00+08:00",
      "status": "published"
    }
  ]
}
```

格式以已交付的 `docs/api.md` 为准，旧 data 草案已废弃。空列表返回 `{"items":[]}`；详情和报名返回 item。后台只返回已发布数据，按 createdAt DESC、id ASC 排序，A 保留顺序取前 3 条。首页挂载或重试重新请求，后台更新后刷新即可读取。示例为首页所需字段，完整接口还有 rules、createdAt、updatedAt、registrationOpen。

`src/lib/competition-preview.ts` 已复用 B 的 getCompetitions 字段校验、items 解析与公共请求工具，没有新增第二套请求系统。

B 负责配置 Vite 的 `/api` 转发到 C 的本地后台（原前端端口 3000，建议后台 3001），部署时配置同源 `/api` 反向代理。A 本次不修改公共开发配置；未配置转发或无后台时首页会显示可重试错误，不显示虚构赛事。

## 路由接入

`src/App.tsx` 已接入赛事及管理页面；`AdminAccess` 为管理区统一身份检查和退出布局，仅报名管理仍待 D5 交付：

| 路由 | 交付人 |
| --- | --- |
| `/competitions` | B |
| `/competitions/:id` | B |
| `/admin/login` | D |
| `/admin/competitions` | D |
| `/admin/competitions/new` | D |
| `/admin/competitions/:id/edit` | D |
| `/admin/competitions/:id/registrations` | D |

`/admin` 确认身份后进入比赛管理，未登录跳到 `/admin/login`。新建页和报名占位页同样受保护。临时服务失败显示重试，不能当成未登录；后台接口仍由 C 独立鉴权。退出调用真实 logout 并回登录。报名管理占位不能算 D5 已完成。

## 本地启动

安装 Node.js 22.13 或更高兼容版本，在仓库根目录执行：

```sh
npm ci
npm run dev
```

根目录复制 `.env.example` 为 `.env.local`，确认 API_PROXY_TARGET 指向后台，配置变化后重启 Vite。后台按 `server/README.md` 初始化配置和数据库，在另一终端启动。浏览器以终端提供地址为准（默认 `http://localhost:3000/`）。构建检查：`npm run lint`、`npm run build`。
